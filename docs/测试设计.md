# 测试设计

## 范围

被测对象是单进程 FastAPI 模拟期权交易服务。测试覆盖认证、账户、行情、订单、保证金、净仓、清算、WebSocket、网页和授权边界。未设置 `BASE_URL` 时，fixture 启动并关闭服务；每个 API、UI、安全用例前重置状态，共享状态测试应串行运行。

## 场景

| 模块 | 检查内容 |
|---|---|
| 认证 | 登录、错误凭证响应、验证码单次使用与过期、改密边界、令牌撤销、非法 Unicode |
| 账户与行情 | 种子余额、合约字段、ticker、指数价对保证金的影响 |
| 订单与撤单 | 成交、挂单冻结、参数边界、撤单释放、状态筛选、平多和净仓均价 |
| 保证金与清算 | ATM/OTM 手算、维持保证金边界、混合持仓、短缺和用户隔离 |
| WebSocket 与 UI | 行情快照及更新；登录、挂单、撤单和持仓展示 |
| 安全 | 服务端验证码、订单 IDOR、令牌授权、参数篡改和测试接口门控 |

## 独立预期与边界

测试规则字面值放在 `tests/support/test_data.py`，金额按规格手算，不调用应用配置或计算函数生成预期。金额用 `Decimal` 比较，不依赖字符串格式。

| 字段 | 有效边界 | 拒绝值 |
|---|---|---|
| 价格 | tick `0.5`，最大 `1000000` | 零、负数、`100.3`、超上限、`1e2`、`1_00` |
| 数量 | `0.1` 至 `100`，步长 `0.1` | 零、`0.15`、超上限、负数、非有限数 |
| 新密码 | 长度 `8` 至 `64` | 长度 `7`、`65`、错误旧密码 |
| 验证码 | 六位、60 秒内 | 缺失、空、错误、错配、重复和过期 |
| 请求体 | 合法 JSON 对象和普通十进制数 | 未知字段拒绝；非对象或孤立代理字符不得导致 500 |
| 清算 | 权益严格低于维持保证金 | 相等时不清算；负可用额不单独触发清算 |

最大价格边界用例会先准备足够余额，避免将资金不足误判为参数拒绝。

## 公式与算例

```text
买单保证金 = 委托价 × 数量
空头保证金 = [max(0.15 × 指数价 − 虚值额, 0.10 × 指数价) + 委托价] × 超出多仓的数量
看涨虚值额 = max(行权价 − 指数价, 0)
看跌虚值额 = max(指数价 − 行权价, 0)
可用额 = 余额 − 挂单冻结 − 已有空仓初始保证金
维持保证金 = Σ[(0.075 × 指数价 + 标记价) × 空头数量绝对值]
权益 = 余额 + Σ(标记价 × 带符号持仓数量)
未实现盈亏 = (标记价 − 持仓均价) × 带符号持仓数量
```

ATM call 指数价 `100000`、卖价 `5000`、数量 `0.1`：`(max(15000,10000)+5000)×0.1=2000`。OTM call 行权价 `110000`、卖价 `2500`：`(max(15000−10000,10000)+2500)×0.1=1250`。

余额 `10000` 时卖出 `0.1` 张 ATM call，收到 `500` 后余额为 `10500`，持仓市值 `-500`，权益为 `10000`。标记价 `60000` 时权益 `4500`、维持保证金 `6750`，触发清算；标记价 `48750` 时两者均为 `5625`，保持 active，升至 `48750.5` 时清算。

卖出 `0.4` 张 ATM call 后余额 `12000`。指数价 `200000`、标记价 `5000` 时初始保证金 `14000`、可用额 `-2000`，权益 `10000`、维持保证金 `8000`。可用额为负但账户仍 active。

## 安全场景

验证码测试直接调用 API，覆盖登录与改密的缺失、空值、错配和错误后重试，并验证错误验证码不会修改密码。演示验证码直接包含在响应中，且没有限速。

`alice` 创建订单后，`bob` 尝试读取或撤销；预期统一 404，`alice` 的订单和冻结金额不变，`bob` 的列表不含其他用户的数据。参数测试覆盖伪造 `username`、`status`、`required` 字段、畸形数值、长合约名、非对象 JSON 和孤立代理字符。

## 运行

```sh
./.venv/bin/pytest -m api
./.venv/bin/pytest -m security
./.venv/bin/pytest tests/unit
./.venv/bin/pytest -m ui
./.venv/bin/pytest --collect-only -q
./.venv/bin/python tools/mutation_check.py
```

变异脚本逐项修改并恢复实现。`KILLED` 表示测试发现变异，`SURVIVED` 表示未发现；基线失败、跳过或运行错误也会令脚本返回非零。运行前取消 `BASE_URL`。JMeter 运行方式和指标见 `perf/README.md`。系统没有真实撮合、期权定价模型或持久化存储；改价不会撮合挂单。
